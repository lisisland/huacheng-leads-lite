# GoodJob 外贸获客功能与数据源审计

日期：2026-10-20  
用途：华橙内部产品理解、使用指导及后续二次开发依据。当前阶段仅分析，不变更业务流程、不发起获客或触达、不上传仓库。

## 1. 结论先读

GoodJob 更接近“带多来源搜索、候选清洗、联系检查和发信流程的综合 CRM”，不是已经打通全球海关买家名单的获客数据库。

最值得保留的是任务留痕、多来源适配、候选去重、来源证据、联系人补全、触达记录与客户商机关联。最需要改的是来源分类、候选质量判定、对象流转和页面信息层级。

本地代码注册了 **37 个数据源定义**：27 个具有企业／网页 search 适配方法、3 个具有贸易统计 trade 方法、7 个没有自动 search／trade 方法。AI 搜索是额外的运行时能力，不包含在这 37 项中。这个数字表示“代码有定义”，不表示全部已配置、全部接口在线或全部适合当前市场。

四个关键判断：

1. **海关统计不等于进口商明细。** UN Comtrade、Census、Comext 回答商品和市场的贸易规模，不能直接输出某家采购商和采购邮箱。
2. **国家企业库不等于客户需求库。** 注册、LEI、CIK、SIREN 等信息主要证明企业身份，不证明正在采购某产品。
3. **来源有绿色状态，不等于真实联网测试通过。** 有些内置源 health 直接返回成功，有些人工入口 health 也成功，页面必须明确区分。
4. **检索结果不等于合格客户。** 搜到文章、政府页面或供应商获奖记录，均不能直接当作买家。

## 3. 先拆开六种“数据源”

| 来源类型 | 能回答什么 | 通常输出 | 不应推导成什么 |
|---|---|---|---|
| 网页／地图发现 | 哪里可能有相关企业 | 网页、商户、官网、摘要 | 已核实公司、现时采购需求 |
| 企业身份核验 | 这家主体是谁、注册在哪里 | 法人名、注册号、地址、状态 | 采购负责人、进口记录 |
| 行业名录／产品注册 | 哪些机构与某行业或产品有关 | 机构、申请人、认证产品 | 一定是经销商或采购方 |
| 采购／授标信号 | 谁发布采购、谁获得合同 | 采购机构、公告、中标供应商 | 仍开放的需求；中标方就是买方 |
| 贸易统计 | 某商品在哪些市场有贸易 | 国家、商品编码、期间、金额、数量 | 具体进口商或联系人 |
| 企业级货运／提单 | 谁与谁发生过可观察的贸易 | 托运人、收货人、货描、日期 | 联系人许可、正在寻找新供应商 |

建议以后先按“找公司／核实公司／找采购信号／看市场／查贸易关系”组织来源，不按“免费／付费”作为首要导航。

## 4. 海关和贸易类：当前最容易误解的部分

### 4.1 UN Comtrade：自动统计适配，非买家名单

- 本地 ID：un_comtrade；代码有 trade 方法，不属于普通企业 search 列表。
- 查询围绕报告国、伙伴国、进出口方向、商品编码、期间和统计分类进行；适配区分年度／月度及分类版本。
- 代码按是否提供凭据选择公开预览或数据接口；公开预览有返回限制，不能当作全量数据库。
- 输出为金额、净重、数量、单位、统计状态等，没有企业名称和采购邮箱字段。
- 合适用途：比较市场规模、结构、变化，辅助决定研究方向。统计发布日期和缺失数据必须保留。
- 局限：商品分类不能与销售口语产品名称直接等同；不同年份和统计口径需可比。

UN 官方将 Comtrade 定位为按商品和贸易伙伴汇总的年度、月度贸易统计。[官方说明](https://comtrade.un.org/)

### 4.2 美国 Census International Trade：自动统计适配，需配置 Key

- 本地 ID：us_census_trade；有 trade 方法。
- 本地适配器要求美国为报告国、一个四位伙伴代码、月度频率、一个 2／4／6 位 HS 商品码，期间为连续 1—36 个月；这些是本项目实现限制，不是官方全部能力。
- 官方 API 当前说明查询需 API Key；不能因项目标为 free 就认为免配置。
- 输出美国与伙伴的商品贸易统计，不输出进口企业或提单收货人。
- 对南非可以研究“美国与南非的某商品贸易”，不能据此声称覆盖南非全部进口。

出处：[Census 国际贸易 API](https://www.census.gov/data/developers/data-sets/international-trade.html)。

### 4.3 Eurostat Comext：自动统计适配，不能当全球数据

- 本地 ID：eurostat_comext；有 trade 方法；本地使用 DS-045409 数据集。
- 本地适配主要针对欧盟报告国、月度、单商品及有限期间的查询，具体参数受代码校验约束。
- 适合欧盟与伙伴之间的货物贸易研究，不是南非法人名录，也不是全球企业级交易明细。
- 代码明确保留欧元口径，不应将原值显示成美元；跨来源比较须统一币种、期间、流向和分类。

出处：[Eurostat 货物贸易数据库](https://ec.europa.eu/eurostat/web/international-trade-in-goods/database)。

### 4.4 中国海关统计：只有人工辅助入口

- 本地 ID：china_customs_statistics；accessMode=website_controlled。
- 代码提供官方入口和说明，没有自动 search 或 trade 实现。
- 它在目录中出现不等于配置后能采集报关单、进口商、采购邮箱。
- 本地文案也明确为市场验证入口，不自动采集企业级明细。
- 二开应将其放入“市场研究／人工查询”，标注“手动查询”，不与可执行搜索源使用相同绿点。

### 4.5 ImportYeti：项目未接自动接口；服务商本身已有 API

- 本地 ID：importyeti；accessMode=manual_assisted；没有 search／trade 实现。
- 目前工作方式是人工查询、核实，再把企业或结果链接交回系统；勾选来源不能让 Worker 自动抓取提单。
- 本次核对发现 ImportYeti 已有官方 API，文档包含美国及墨西哥进出口记录等能力，需 Key 和数据 credits。这与本地“人工辅助”的旧适配不是一回事。
- 因此准确结论是“**GoodJob 本地版本没有集成 ImportYeti API**”，不是“ImportYeti 没有 API”。
- 其美国海运说明还提到别名、保密请求等覆盖缺口；不同数据集范围应分别确认，不能将某一数据集的限制推广到整个平台。
- 即使以后接入，货运历史仍只是采购行为证据之一，收货人可能是代理或物流主体，联系方式和当前采购状态仍需核实。

出处：[ImportYeti 官方 API](https://docs.importyeti.com/docs/getting-started)、[美国海运数据说明](https://www.importyeti.com/our-data)。

### 4.6 对“已经有海关数据”的准确说法

本项目具备贸易统计查询代码，并提供若干人工研究入口；尚不能认定已经拥有可自动检索、覆盖全球、带联系人、可商用转售的企业级海关数据库。

贸易统计应进入“市场研究”结果区；企业和交易关系进入“公司／贸易关系”区。两种记录不应直接混入同一客户表。

## 5. 国家企业库、身份库和行业库逐项审计

下表中的“API”仅表示本地存在适配；联系人列按实际映射说明，不保证外部源所有记录都有值。

| 来源 / 本地 ID | 实际覆盖与查询方式 | 本地能得到什么 | 限制与合适定位 |
|---|---|---|---|
| GLEIF / gleif | 全球取得 LEI 的主体；名称全文或精确 LEI | 法人名称、LEI、注册国家、城市、状态相关证据 | 不覆盖所有中小企业；代码不返回官网和联系人。优先做身份核验，不宜用产品词硬搜法人名 |
| Companies House / companies_house | 英国注册主体；名称或公司号；需 Key | 公司名、注册号、注册／地址证据 | 不是全球工商库，官网为空；注册存在不证明业务匹配 |
| SEC EDGAR / sec_edgar | SEC 申报主体，支持 CIK 等核验 | 主体、CIK、ticker、申报档案和部分业务说明 | 不是所有美国企业；界面 apiKey 字段实际填写“系统名 联系邮箱”作为 User-Agent，非购买密钥 |
| 法国企业搜索 / fr_company_search | 法国企业名／SIREN；有国家跳过逻辑 | 法人名称、SIREN／SIRET、NAF、地址、注册状态相关信息 | 官网和采购联系信息不直接提供；法语词和 NAF 与商品词不等价 |
| OpenCorporates / opencorporates | 聚合多法域企业登记，需 Token | 企业名、登记法域、公司档案 | 可用范围、许可、字段取决于服务；法域码不能直接当国家名，不能当全球全量库 |
| Wikidata / wikidata | 开放实体知识库，英文实体检索；补取 P856 | 实体名称、简介、部分官网 | 不是官方工商库；能命中产品、概念等非公司实体；当前国家有沿用查询条件的情况，不能当已核实事实 |
| ROR / ror | 科研／教育／医疗等机构 | 机构名称、标识、国家、部分官网 | 适合特定机构研究，不是一般经销商数据库 |
| NPPES / nppes | 美国医疗服务提供者／机构 | NPI、机构名、注册地址、部分电话等 | 医疗身份不代表进口权或采购意图，不适合泛行业默认搜索 |
| openFDA 510(k) / openfda_510k | 医疗器械申报记录，按器械名称检索 | 申请人、产品、K 编号、决定时间、部分联系人姓名 | 申请人可能是制造商；本地 contactInfo 为空；不能把联系人姓名当邮箱或将其当通用 FDA 企业库 |
| 墨西哥 DENUE / mexico_denue | 墨西哥经营单位名录，需 Token | 商号／法人名、经营类别、地点，部分电话、邮箱、网站 | 经营场所和法人可能一对多，应处理分店归并；未自动证明进口行为 |
| FMCSA QCMobile / fmcsa_qcmobile | 美国承运商，需 WebKey | 法人名、USDOT、承运状态及部分公开联系方式 | 物流行业身份核验和发现，不是通用进口商源 |

### 身份库的三个使用陷阱

1. **公司名称检索与产品检索混用。** 例如 GLEIF 使用拼接后的全文条件查询实体，不能保证某产品关键词出现在注册法人名中。
2. **输入条件被写回结果。** 网页和部分参考源会把查询国家、产品词作为候选国家、业务的兜底值；这些应标成“根据查询推定”，不是“来源确认”。
3. **官方源权威性被扩大。** 官方能证实注册号，不表示同时证实官网、采购角色、邮箱和需求。每个字段应有独立来源与核验状态。

GLEIF 官方说明其免费检索面向 LEI 数据池；Companies House 与 SEC 官方入口也各有明确覆盖范围：[GLEIF](https://www.gleif.org/en/lei-data/lei-search/about-lei-search/how-to-use-lei-search)、[Companies House](https://developer.company-information.service.gov.uk/)、[SEC API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)。表内具体字段和限制主要依据本地适配代码。

## 6. 公共采购和中标来源：有需求信号，但买卖角色必须拆开

| 来源 / ID | 本地接入 | 返回主体与信号 | 应如何理解 |
|---|---|---|---|
| 欧盟 TED / eu_ted | API，无需 Key | 公告关联采购机构和采购描述 | 主要面向欧洲公共采购；不能等同于当地零售经销商名录 |
| 世界银行采购 / world_bank_procurement | API，无需 Key | 项目采购机构、项目公告，部分公开联系人 | 项目制采购，不是世界银行持有的所有公司采购清单 |
| 英国 Contracts Finder / uk_contracts_finder | API，无需 Key | 英国采购公告、采购方及描述 | 有区域和公告状态限制；检索为空不证明当地没有相关企业 |
| 英国 Find a Tender / uk_find_a_tender | API，无需 Key | 本地映射 buyer 作为公司、公告作为信号 | 必须区分采购方、获奖供应商和公告时间，不可扁平化为一家公司 |
| USAspending / usaspending_awards | API，无需 Key | 本地将 Recipient Name 映射为公司 | **合同获奖方／供应商**，不是当然的采购买家；适合作为渠道、同行或合作研究线索 |
| 美国 SAM.gov / sam_opportunities | API，需 Key | 政府采购机会、采购机构和公告联系信息 | 部门联系人是针对特定公告，不必然是泛产品采购负责人 |
| 巴西 PNCP / brazil_pncp | API，无需 Key | 巴西采购机构和公告 | 关键词、本地语言、时间范围影响结果；先看是否仍开放 |
| 新加坡 GeBIZ / singapore_gebiz | API，无需 Key | 本地优先 supplier_name，缺失时才用 agency | **优先映射中标供应商**；没有联系方式也会形成候选，不应自动当成买家 |
| CanadaBuys / canadabuys_open_data | 文件辅助，无自动 search | 下载官方文件后人工处理 | 名称中有 import 能力标签，不代表已经是自动海关或企业进口数据库 |
| 韩国 KONEPS / koneps | 网站辅助，无自动 search | 人工查询公告后登记 | 不是已接入韩国国家采购 API 的证据 |

对一般消费品分销客户发现，公共采购源通常不是首选；对工程、公共设施、医疗机构采购等场景可能更有价值。这是来源与场景的匹配判断，不是对所有行业的统一排名。

二开应把公告建为独立对象：公告编号、产品类别、买方、供应商、发布时间、截止时间、状态、金额和原始链接。再决定关联哪个企业，避免中标供应商与采购部门混在公司列。

## 7. 其余来源：哪些是搜索、补全，哪些只是入口

| 来源 | 当前实现定位 | 重点边界 |
|---|---|---|
| AnySearch | 网页搜索 API 适配；允许匿名低频模式，也支持 Key | 内置入口不保证匿名调用稳定或有足够额度；需真实请求判断 |
| Serper、Brave、SerpApi | 第三方搜索 API，需分别配置凭据 | Serper 不是 Google 官方 Places；搜索只返回网页，不天然返回公司 |
| Google Places | 官方地图商户 API | 商户名、地址、部分网站／电话；不等于采购邮箱或决策人数据库；需单独开通和配置 |
| Apollo、PDL | 商业企业／人员数据适配，存在 search 与 enrich | 覆盖、联系人权限、付费字段需实际账号验证；本地未逐项验收 |
| Hunter | 主要作为域名联系人／邮箱补全；代码也有 search 方法 | 应在已确定企业域名后使用，不应宣传为“自带无限企业名单” |
| EPREL | 欧盟产品注册网站辅助入口 | 能研究制造商和产品，不代表有自动产品库 API 采集 |
| EU Ecolabel | 欧盟认证目录辅助入口 | 认证主体并非自动成为采购方 |
| SBIR/STTR | 美国创新获奖企业人工研究入口 | 当前没有稳定自动 search 适配；获资助只是一种业务信号 |
| AI 搜索 | 独立模型配置，支持联网引用时可形成候选 | 不是注册库或海关库；普通生成成功与真实联网检索成功需分开记录 |

官网抓取、联系方式提取、CLI、Lfind、Runner 是执行或研究方式，不应再作为与 GLEIF、海关库平级的“数据库”。它们需要网页、外部工具或授权来源才能得到事实。

## 8. 对当前市场覆盖的实话

本地这组来源中，**没有找到专门的南非国家企业注册库适配器，也没有南非企业级海关交易明细适配器**。不要因 GLEIF、Wikidata 或世界银行具有国际覆盖，就认为已覆盖南非所有中小经销商。

英国、法国、美国、墨西哥、巴西、新加坡等国家源有明显地域或行业限制。选择目标国家后，应先展示来源适用性；不适用的源显示“地域不适用”，而不是运行后给一个没有解释的 0。

对任何新增市场，评估新来源应先核对五项：覆盖对象、更新日期、能返回的业务字段、自动调用许可、真实样本质量。先小样本验收，再决定是否接入；本报告不把未核对的外部服务当作已可用方案。

## 9. 实际获客功能全景

| 环节 | 已见功能 | 本次证据／当前边界 | 业务上应该得到的结果 |
|---|---|---|---|
| 描述目标 | 自然语言、结构化表单；产品、国家、客户类型、排除词 | 页面与 parse-goal 代码；AI 结果可编辑，实际执行使用编辑后的结构化值 | 一份清楚且可复核的搜索条件 |
| 标准搜索 | 选择来源、数量，后台任务和查询快照 | 页面、launch、Worker、历史执行日志 | 少量可验证候选，而不是承诺数量一定满足 |

### 三个对象不能混为一谈

“搜索候选”是自动收集、尚未确定价值的结果；“搜客清单”是选入日常工作的候选；“线索／客户／商机”是进入销售管理的不同对象。它们有关联，但不是几个页面对同一数量的重复展示。

本次实际页面显示：最新历史任务为 18 条候选，研究就绪 0；搜客清单 0；线索 0。页面也明确提示从搜索结果勾选加入清单。因此“搜到了 18 条，另一个页面还是 0”不一定是数据丢失，而是没有完成对象流转。这个动作现在提示不足。

## 10. 页面为什么显得乱：可定位的问题

### 10.1 主任务被过程展示挤走

当前页依次摆放搜索简报、AI 解析、来源设置、类似聊天的执行历史、候选预览、统计卡、结果表、清洗区和计划。候选在过程区和表格中重复出现，而用户最需要做的是快速决定“保留谁、排除谁、下一步做什么”。

建议：结果页为主；执行进度变为一条可展开状态栏；日志、清洗报告、原始响应进入任务详情。搜索表单完成后折叠成条件摘要。

### 10.2 噪声结果被当成公司，是实质性数据问题

截图包含监管、公共卫生和学术内容域名，以及被截断成 E、About E 的标题。本地 webResultToLead 使用搜索标题的前一段作为公司名、URL origin 作为疑似官网；虽然有社交／招聘等域名过滤，但不足以识别文章和监管页面。

因此只换颜色、减少列，不能解决候选不可信。需要增加“实体类型判定”：公司／机构／公告／文章／目录／未知。无法确认的内容保留在研究资料区，不能直接进入公司候选默认视图。

### 10.3 搜索条件、来源事实与模型推断混在一起

查询国家可能被复制到候选；片段可能被当作业务；网页域名可能被直接当官网。用户看不到这些字段各自的证据等级。

建议详情中区分“来源直接给出”“官网确认”“模型推断”“尚未核实”。列表只给简明状态，展开后再看逐字段证据。

### 10.4 一排 6 分不具有比较价值

本地 scorecard 按企业可信度 25%、画像匹配 35%、联系准备 25%、采购／互动信号 15%计算行动优先级。未完成画像和联系方式检查时，多条候选可能落在相近低分。

所以截图同分不能直接证明模型没工作，也不能将它解读为成交概率。应展示“待核实业务／缺联系人／缺采购信号”等具体缺口；完成最低核验后再用于排序。

### 10.5 技术词占据核心列，业务动作被弱化

单来源支持、规则归纳、来源记录、核验、CLI 背调、原始英文失败原因同时展示，用户仍不知道这家公司是否符合目标。联系姓名和地址列还可能装入“No public contact…”等诊断文本。

建议将诊断状态与业务字段分开；无联系人显示“未找到联系人”，具体失败原因进入详情。不要把英语错误信息当联系人姓名或邮箱保存／展示。

### 10.6 长截图重复菜单，暂不判为真实菜单重复缺陷

用户提供的长图里菜单多次重复。本次实际 DOM 导航与只读页面检查，没有证明这些模块真的被重复注册；长截图拼接固定侧栏也会造成重复。因此此项记录为“截图现象，需真实滚动复现”，不据此提出删除多份菜单代码。

### 10.7 “来源证据 0”与来源记录同时存在

当前历史任务过程区显示 0 来源证据，结果又有来源记录链接。可能统计的是不同层级，例如任务事件证据与候选字段证据；本次没有证明哪个计数错误。二开应统一口径并加说明，不能把某处的 0 等同于全部无来源。

## 11. 建议的精简信息架构

保留六个核心入口：今日待办、找客户、客户清单、沟通与跟进、商机、设置。资料、报表、单据等放入更多应用；任务日志和源配置不再作为与结果竞争的主内容。

“找客户”内部建议分三块：

1. **新建搜索**：目标、排除条件、适用来源摘要。高级设置默认折叠。
2. **搜索任务**：条件、运行状态、原始命中／有效公司／待核实数量，点开才看过程。
3. **结果工作区**：企业候选、采购公告、研究资料分别展示。默认只看企业候选。

企业列表默认保留：公司与官网、国家／角色、匹配理由、公开联系渠道、核验缺口、下一动作。日期、详细来源、评分分项、运行 ID 和技术错误放入详情。

右侧详情使用“概览、业务匹配、联系人、采购／贸易信号、来源证据、跟进记录”标签。详情显示事实、日期、来源与不确定性；列表负责决策。

数据源设置至少展示：覆盖市场、来源类型、自动／手动、凭据状态、最近真实测试时间、最近成功调用、费用／限流入口。区分“无需 Key”“已保存”“已测试”“本次适用”“本次已调用”，不要统称“已连接”。

## 12. 后续二开优先级与验收标准

| 优先级 | 改造项 | 验收标准 |
|---|---|---|
| P0 | 来源能力分层 | 中国海关、ImportYeti 等人工入口不再表现为自动源；贸易统计不进入公司结果 |
| P0 | 候选实体分类 | 含文章、监管和公司网站的样本能分类；未知保留待核实，不能仅靠域名白名单硬删所有机构 |
| P0 | 条件可复核 | 启动前展示产品、市场、买方类型；未指定市场明确显示全球；解析后的编辑值与运行快照一致 |
| P0 | 列表与详情分离 | 普通用户无需读日志即可判断主要匹配理由、缺口和下一步；来源原文仍可追溯 |
| P0 | 对象流转清楚 | 候选加入清单、排除、转线索各有明确反馈与数量变化，失败不假成功 |
| P1 | 来源按市场／行业路由 | 不适用来源有跳过原因；0 命中、失败、未执行分别统计 |
| P1 | 采购角色与时间建模 | 采购方和中标供应商分字段；过期公告不能显示为当前开放采购 |
| P1 | 逐字段证据与缺口 | 推断国家、来源官网、确认官网可区分；评分有原因和缺失项 |
| P1 | 联系方式和发送闭环 | 分别验收 SMTP 受理、退信、真实回复同步；外部账号未配时显示具体缺项 |
| P2 | 企业级贸易服务新适配 | 先完成来源授权、数据集覆盖和字段样本验收，再接入和计算价值 |
| P2 | 定时／超级搜索体验 | 有预算、停止、恢复和新增去重说明，业务指标与执行指标分开 |

首轮应验证“有效公司占原始命中比例、目标市场匹配率、角色识别准确性、官网确认率、有效联系渠道覆盖率、单条合格候选成本”。回复、实质沟通、商机和订单作为后续漏斗指标，不能用候选数量代替。
