# 非洲电商公开资料模块：实现与实测

日期：2026-10-20。用途：会议屏、教育白板及其他普通商品的通用公开资料研究。产品关键词由用户输入，不固定品类。

## 入口与已实现能力

打开 http://127.0.0.1:15188/focus.html ，左侧选择「电商资料」。与原系统共用账号，仍使用桌面「GoodJob 企业资料工作区」快捷方式启动。

本次新增 3 个独立电商研究连接定义，不混入原 37 个企业／贸易来源的统计：

| 平台 | 市场 | 入口 |
|---|---|---|
| Takealot | 南非 | https://www.takealot.com/ |
| Jumia Kenya | 肯尼亚 | https://www.jumia.co.ke/ |
| Konga | 尼日利亚 | https://www.konga.com/ |

支持的工作方式：

1. **关键词读取**：选择平台后，服务端先读取 robots，再尝试读取一页公开搜索结果；不需要大模型或卖家 API Key。不自动登录、不绕过访问验证。
2. **HTML 导入**：在能正常浏览网站的浏览器保存页面，输入对应原始 URL 后上传或粘贴 HTML。
3. **商品页文字导入**：输入具体商品页 URL，复制可见文字；第一行作为商品名称，只有明确价格行和编号被提取。标记为用户导入、未在线复核。

已实现 JSON-LD Product / ItemList、多产品图谱，以及 Jumia 公开商品卡片、具体商品页 meta 的解析。页面变化或仅有浏览器动态内容时，显示“页面未解析”，不冒充无商品。尚未加入后端浏览器自动渲染适配。

## 字段与事实边界

商品名称、原始 URL、品牌、SKU、展示价格与币种、卖家展示名称、评分、评价数量、结构化规格、公开评论摘录、解析方式、采集／导入时间、价格出处。

字段仅在页面实际提供且当前解析规则能识别时填充。真实销量固定保留未知，不从评价数推算；不生成成本、采购意向或利润。用户导入的时间不是商品页面更新时间。评论正文与评价数量分别展示。

产品证据可以单独打开查看，记录可重新加载并导出 JSON。原始网页脚本不会执行，不保存完整上传 HTML，仅留结构化字段。记录按当前登录用户与团队隔离，保存于 GoodJob/.local-runtime/marketplace-research，最近最多 50 条。它是本机留档，尚未迁入 MySQL；更换电脑需迁移该目录。

## 实际连接结果

在本地服务通过真实 UI 搜索 `interactive whiteboard`，当次结果：

| 平台 | 真实结果 | 含义 |
|---|---|---|
| Takealot | HTTP 403 | 请求被拒绝，未绕过；未获得商品记录 |
| Jumia Kenya | ECONNRESET；普通 Edge 访问也连接关闭 | 尚未读到内容，不能判断是否有商品 |
| Konga | 服务端 ECONNRESET | 普通 Edge 后续读到 robots，规则对通用机器人禁止 `/search`；没有继续自动读取搜索路径 |

Konga 具体商品页另一次普通 Edge 访问也出现连接关闭。Google、Serper 的本机基础 HTTPS 探测同样出现连接重置，因此不能把这些失败统一归因于平台缺乏数据、需要登录或商品不存在。

**本次没有完成三平台的在线自动采集成功验收，实际在线提取数量为 0。** 三平台连接定义、自动读取流程、导入、字段解析和证据展示已经实现；真实外网采集仍受上述条件影响。

最初定位相关公开页面使用了网页搜索工具，其搜索索引曾返回教育白板和会议屏页面；该工具的结果不等于本机服务可以实时读取。没有把搜索索引的历史价格复制成在线采集结果。

## 已通过的验证

- 后端与前端 TypeScript / 构建通过；原系统体积较大的前端 chunk 警告仍保留。
- 单元测试覆盖 JSON-LD、Jumia 卡片、文字导入、币种、规格、评论、销量未知、来源标签、错误 URL／跨域／带凭据链接拒绝。
- 模拟 robots 拒绝时不再读取搜索页；网络重置显示失败，不显示空搜索。
- 登录实际服务，通过三个平台的真实搜索请求，按来源展示不同结果并留档。
- 真实 HTML 导入接口以明确标注的测试样例校验：解析 → 保存 → 刷新 → 重读 → 商品详情。测试样例随后已移除，未作为真实商品展示。
- 未登录请求研究历史返回 HTTP 401。
- 桌面及 390px 手机布局通过，无页面运行异常。

浏览器验证：work/check-marketplace-ui.cjs。解析与访问边界测试：GoodJob/backend/src/marketplace-research-test.ts。

## 后续验收重点

1. 在网络能够正常访问的平台，对真实教育白板／会议屏商品页逐字段比对价格、币种、规格、卖家和日期。
2. 对只在浏览器渲染后出现的字段，增加普通浏览器读取适配，并保留相同的访问规则和失败状态；不能仅因找到内部接口就承诺其稳定性。
3. 适配更多实际可访问的本地平台或本地经销商公开目录，按地域与数据覆盖选择。
4. 将商品证据与企业背景记录建立人工确认的关联，而非把所有平台卖家自动判定为合格采购客户。
