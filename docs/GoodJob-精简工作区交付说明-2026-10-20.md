# GoodJob 精简工作区

日期：2026-10-20。适用场景：小团队集中整理企业候选、来源、联系资料及背景核验档案。

## 如何打开

服务运行后打开 http://127.0.0.1:15188/focus.html 。使用原 GoodJob 账号；同域登录状态有效时可直接进入。

桌面新增「GoodJob 企业资料工作区」快捷方式，启动脚本为 GoodJob/start-focus.ps1。原「GoodJob 外贸获客」入口仍打开完整系统。精简页左下角也能打开完整系统。

这是独立前端入口，继续依赖原 GoodJob 后端和数据库，不是已拆成独立部署的产品。

## 当前可用

| 页面 | 行为与数据 |
|---|---|
| 企业发现 | 读取原系统全部可见候选，按关键词、市场、来源和联系资料状态筛选；每页 12 条 |
| 新建搜索 | 结构化输入产品、市场、类型、排除词；主动选用已配置的来源；调用原启动接口 |
| 登记官网 | 最多 12 个链接，复用原登记接口；只登记、不自动采集 |
| 企业详情 | 概况、核验摘要、结构化联系人、原始联系字段、来源证据、背调档案分开展示 |
| 研究清单 | 加入原系统 shortlist，继续共用原候选记录 |
| 数据来源 | 将来源目录分成网页地图、企业登记、采购公告、贸易统计、贸易明细入口、联系补充、产品目录、AI |
| 搜索任务 | 最近最多 100 条任务，展示概要及各来源状态，原始事件默认折叠；任务执行时定期刷新 |

当前读取接口返回 37 条历史候选、38 项目录（37 个静态来源加 AI）、3 个历史任务。这是当次检查快照，不是固定产品指标。

## 关键边界

- 联系人观察日期存在才显示时间；缺失显示未知。资料超过 90 天是本界面的提醒阈值，不代表该联系方式已失效。混合记录逐条展示时间。
- 不把系统记录创建日期等同联系方式更新时间，不把“有联系方式”显示成“已有效联系”。
- 贸易统计与企业身份登记不能直接等同采购商名单或采购意向。
- “已配置可选”来自原后端 ready/enabled，不意味着刚刚通过真实网络测试；连接记录的时间单独显示。
- 新页面读取已有背调档案；发起新背调、编辑原系统连接凭据、复杂资格审核仍在完整系统操作。
- 未在精简页加入发信、自动外发、报价、订单、审批、知识考试等模块。
- 当前未新增 Amazon、阿里国际站或本地电商采集接口，不生成电商销量、利润或市场前景数据。
- 页面改造不会自动修复原搜索命中的论文、监管网页、供应商角色或错误国家。所有旧候选仍保留，核验状态单独展示。

## 后续可分模块建设

1. 来源覆盖：每条企业资料保留来源、原始 URL、观察日期和角色；搜索时显示真实来源结果数与失败原因。
2. 企业背景：把企业身份、业务、地区、店铺关系和联系字段分别核验，保留冲突和未知值。
3. 电商资料：逐个平台确认可用接口与许可，保存商品 URL、SKU、规格、币种、含税口径、价格类型、采集时间；评论与平台展示销量保留原始口径。不能把零售报价直接当批发价。
4. 联系资料：记录公共业务联系方式的来源、实际验证方式和时间；没有公开资料的企业不能承诺自动补齐。

## 验证记录

- `npm run build --workspace frontend`：TypeScript 与 Vite 多入口构建通过。原系统大体积 chunk 提示仍存在；精简页单独打包。
- 实际服务浏览器检查：登录、读取真实数据、搜索过滤、详情四页签、Esc 关闭、数据源分类、任务详情、桌面及 390px 手机布局通过，无页面运行错误。
- 浏览器搜索提交被测试拦截；仅检查 UI 流程、CSRF 与幂等请求头，不执行真实外部搜索、不消耗搜索服务额度。
- 捕获的通用工业配件搜索请求使用后端 `launchLeadFinderSchema` 校验通过。
- URL 安全、目录状态合并、人工源不可选、联系方式日期未知及老旧资料识别检查通过。
- 登记官网与加入清单写入接口已接线；此次验证未新增或修改真实客户记录。新页面尚未完成收费搜索和新背调的端到端验收。
